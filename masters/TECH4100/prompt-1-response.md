## 2. UX Development Life Cycle — the MOST important part

For **each phase**, use the same simple recipe:

### 2.X Name of the phase

**1. What is it?**  
→ Explain the phase simply.

**2. Purpose**  
→ Why does this phase exist?  
→ What problem does it try to prevent or solve?

**3. Activities / Techniques**  
→ What does the UX designer actually do here?  
Examples: interviews, surveys, personas, prototypes, usability testing, depending on the phase.

**4. Why does it matter?**  
→ How does this phase improve the user experience?

**5. Apply it to X**  
→ How could this phase be used to improve X?

**6. Source**  
→ Use 1–2 references to support your explanation.

This directly targets **18 out of 30 marks**: lifecycle explanation + purpose/objectives + activities/techniques.

## 3. Current UX Analysis of X

Keep it simple:

### 3.1 Strengths
Choose **2–3 good things**.

For each one:

**What works → why it is good UX → evidence/source**

### 3.2 Weaknesses
Choose **3 strong problems**, not 10 tiny ones.

For each:

**What is the problem?**  
→ evidence/source  
→ how does it affect the user?

### 3.3 Areas for Improvement
Just show:

**Problem → what needs to improve**

Do not give the full solution yet.

For HD, the marking guide wants a very strong analysis of **strengths, weaknesses, and areas for improvement**.

## 4. Recommendations

Use this formula:

**PROBLEM → SOLUTION → WHY → UX PRINCIPLE → SOURCE**

For each recommendation:

### 4.X Recommendation — [name]

- **Problem:** what is wrong with X?
- **Recommendation:** what should change?
- **UX phase:** which lifecycle phase is connected to this?
- **Technique:** interview? prototype? usability test?
- **Why:** how will this help the user?
- **Evidence:** which UX principle or best practice supports your idea?

Aim for about **3 strong recommendations**.

Do not write only:

> “X should improve navigation.”

Instead think:

**navigation problem**  
↓  
**specific change**  
↓  
**UX principle that supports it**  
↓  
**technique to test it**  
↓  
**expected improvement**

That is what turns a simple opinion into proper analysis.

## 5. Conclusion

Answer only 3 things:

**What did you analyse?**  
**What were the main problems?**  
**Why would following the UX lifecycle help X?**

Done.

## Simple HD checklist

For every important section, ask yourself:

**Did I explain WHAT it is?**  
**Did I explain WHY it matters?**  
**Did I explain HOW it works?**  
**Did I connect it to X?**  
**Did I support it with a source?**

If the answer is **yes** to all five, you are aiming directly at the HD criteria: comprehensive explanation, well-justified purpose, detailed techniques, strong analysis, and accurate referencing. 

One last rule: **do not spend most of the report only explaining theory.** Explain the theory, then connect it to **X** as often as possible.
